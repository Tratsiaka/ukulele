# critic
## gaps
- Условия Vercel прямо запрещают скрейпинг и прокси, на которых держится весь импорт песен: Три измерения (sources-ru, sources-en, infra-legal) строят импорт песен на Vercel relay. Acceptable Use Policy Vercel (ред. 21.04.2026), раздел 2 «Prohibited Activities», запрещает «Scrape, proxy, act as a VPN, or host media for hot-linking». На странице Fair Use Guidelines (обновлена 12.11.2026) в блоке «Never fair use» перечислены «Proxies and VPNs» и «Scrapers» (verified_live=true: WebFetch AUP плюс grep HTML страницы fair-use). Нарушение грозит паузой проекта или всего аккаунта, и тогда упадёт уже работающий relay к Neon у существующего приложения. Завести второй аккаунт, чтобы изолировать риск, нельзя: AUP отдельно запрещает «create multiple accounts» ради обхода fair use. => Vercel оставить только для существующего relay к своему Neon: это «функция, которая обращается к своей БД или API», то есть допустимый сценарий. Чужие сайты Vercel не трогает. Как перестроить импорт, см. конфликт «хостинг прокси». Явного запрета скрейпинга в Service-Specific Terms Cloudflare Developer Platform поиском не нашёл (verified_live=false, перед деплоем перечитать Self-Serve Subscription Agreement). Neon теперь отсылает к AUP Databricks, текст не проверен (verified_live=false).
- Публичность репозитория GitHub Pages: На бесплатном GitHub Pages публикуется только из публичного репозитория, для приватного нужен GitHub Pro, Team или Enterprise (verified_live=false: подтверждено документацией GitHub «About GitHub's plans» и вторичными источниками, страница GitHub.com вживую не открывалась). Значит, публичными станут docs/, тестовые фикстуры, стартовые песни и выбор GPL-зависимостей. Оплатить Pro из BY, скорее всего, не получится. => Исходить из того, что репозиторий публичный. Реальные HTML-страницы песен как фикстуры держать вне репозитория (каталог в .gitignore, например fixtures-private/, или отдельный приватный репозиторий без Pages). В публичной части только синтетические фикстуры той же DOM-структуры с текстами из общественного достояния. В docs/ никаких импортированных текстов, только код и собственный набор песен из общественного достояния.
- Общий origin с существующим PWA на <user>.github.io: Оба приложения окажутся на одном origin <user>.github.io. Общими будут IndexedDB, localStorage, квота, решение navigator.storage.persist() и cookie. Если у старого приложения service worker зарегистрирован со scope '/' (корневой репозиторий <user>.github.io), он перехватит и /uke/: кеш и офлайн-логика сломаются. Проверка CORS по Origin в relay тоже не отличит одно приложение от другого. => В манифесте нового приложения задать "id":"/uke/", "scope":"/uke/", "start_url":"/uke/". SW регистрировать с {scope:'/uke/'}. Проверить scope SW старого приложения и при необходимости сузить его. Дать уникальные имена БД ('uke') и префикс ключей localStorage ('uke:'). Различать приложения на relay по ключу или токену, а не по Origin. Share Target action делать внутри scope (/uke/import). Альтернатива — отдельный кастомный домен для Pages, но его доступность из BY нужно проверять отдельно.
- Неполнота базы аппликатур @tombatossals/chords-db для новичка: Три измерения считают эту базу источником истины для диаграмм, синтеза и проверки по струнам. Живая проверка ukulele.json 0.5.1 (verified_live=true: jsDelivr 200, 215 226 B, разбор Python) показала: базовые аппликатуры верные (C 0003, Am 2000, F 2010, G 0232, Dm 2210, Em 0432, E7 1202, A7 0100, G7 0212, Bb 3211, B7 2322, Bm 4222, E 1402/4442). Но у D7 есть только 2223 (с барре) и формы выше по грифу, а нет учебной 2020, которую pedagogy ставит в L3. Аккорда '5' нет, приглушённых струн нет, строй только standard. В позициях с baseFret>1 лады записаны относительно baseFret. => Завести свой chords.json примерно на 60 аккордов (шейпы новичка): взять chords-db и переопределить D7 на 2020, Fmaj7 на 2410, добавить формы '5'. Пометить «учебная» и «альтернатива» (Em7 0202 вместо Em, E7 вместо E). Хранить абсолютные лады, поле midi пересчитывать под high-G, low-G и баритон. Этот файл становится единой таблицей для диаграмм, сложности, синтеза и проверки по струнам.
- Единая модель сложности аккорда и песни: Таблицы «лёгкий/трудный» расходятся (sources-ru, ux-product, pedagogy), а сложность песни никто не определил формально. От неё зависят «лёгкая тональность», фильтр «сложность», выбор версии и рекомендатор. => Сложность аккорда считать по аппликатуре: diff = число пальцев + 2·барре + 1·(baseFret>1) + max(0, разброс ладов − 1). Расчёт на chords-db (verified_live=true): 0 — Am7; 1 — A7, Am, C, C7; 2 — A, Em7, F (и D7 2020); 3 — Cm, D, Dm, E7, G, G7, F#m 2120; 4 — B7, Eb, Em, Fm, Gm; 5 — Bm, E; 6 — Ab, B, Bb, C#m, F#, Fmaj7. Персональная поправка: diff·(1 − min(0.6, OMC_best/100)) по лучшим результатам OMC для пар с этим аккордом. Сложность песни: D = 0.45·max(diff) + 0.25·средняя diff, взвешенная по вхождениям, + 0.4·max(0, уникальных − 4) + 0.5·[в среднем ≥4 аккорда на строку] + 0.5·[BPM > 120] + уровень боя (0–1). Перевести в 1–5 звёзд и показывать узкое место («Bb; 6 аккордов»). Для калибровки использовать difficulty/ug_difficulty из UG и список beginner на ukulele-tabs.
- Нормализация нотации аккордов: каноническая модель и выбор между H и B: Правило «если в песне есть H, то B — это Bb» есть у трёх измерений, но его недостаточно. Немецкую нотацию отдают muzland при tone= (H, Hsus4) и holychords. На mychords встречается B#m, на akkords.pro A# вместо Bb. Ни tonal, ни ChordSheetJS не понимают H. Ошибка ломает маски «играбельно», транспонирование и диаграммы одновременно. => Каноническая форма аккорда: {root 0–11, quality ∈ [maj, min, 7, m7, maj7, 6, m6, 9, add9, sus2, sus4, 7sus4, dim, dim7, aug, m7b5, 5], bass 0–11|null, alt:boolean, raw}. Конвейер: NFC → гомоглифы (А, В, С, Е, Н → латиница; ♯ ♭ → # b) → токенизатор с русскими суффиксами ('7+'→aug7, '-5' и '7/5-'→b5, 'm7-5'→m7b5, '+'→aug, '7/9'→9, 'maj'/'Δ') → энгармонизм (B#→C, E#→F, Cb→B, Fb→E). Если в песне нет H, но у источника немецкая нотация по умолчанию, B разрешать по тональности: посчитать попадание множества аккордов в 24 диатонических набора при B=си и при B=Bb и взять лучший вариант. Отображать с учётом тональности (бемоли для F, Bb, Eb, Dm, Gm, Cm). В настройках — показывать H или B.
- Каподастр и перенос гитарных подборов на укулеле: Большинство источников гитарные. «Capo 3» в гитарной версии относится к гитарным шейпам: без учёта каподастра звучащая тональность будет неверной для режима «под запись». Аппликатуры и строй у UG-типа Chords гитарные (подтверждено в verify), а 6-струнные табы на укулеле бесполезны. => Парсить каподастр из UG meta.capo и из текста регулярным выражением /(capo|каподастр|капо|кап\.)\s*(на\s*)?([IVX]+|\d{1,2})/i, хранить capoSource и instrumentSource (guitar|ukulele). Звучащие аккорды = записанные + capoSource. Режим «пою сам»: capoSource игнорировать, лёгкая тональность в пределах ±3–5 полутонов от оригинала. Режим «под запись»: перебрать каподастр укулеле c = 0..5, шейпы = звучащие − c, стоимость = Σdiff + 0.3·c. Баритон DGBE: гитарные подборы играются как записаны, с тем же каподастром, без транспонирования. Строки /^[eBGDAE]\|/ из 6 строк табулатуры скрывать по умолчанию, 4-строчные табы укулеле (A|E|C|G) оставлять. Песни UG типа Ukulele Chords не транспонировать автоматически.
- Откуда брать каталог для «+N песен» и бейджей «играбельно» в поиске: Алгоритм с 12-битными масками у pedagogy работает только с песнями, у которых уже известны аккорды. До загрузки страницы у результатов поиска аккордов нет. Chordonomicon без названий, а массовый обход сайтов запрещён правовой схемой. => Для WordPress-источников есть один запрос сразу с контентом: GET /wp-json/wp/v2/posts?search=<q>&per_page=5&_fields=id,title,link,content (verified_live=true: akkords.pro 200, 12 KB, 1.4 с; dieza.net 200, 33 KB, 6.9 с, CORS отражает Origin). Он сразу даёт наборы аккордов для бейджей «играбельно / +1 аккорд» прямо в выдаче. Счётчик «следующий аккорд откроет +N» считать по библиотеке, истории поиска и стартовому набору. Для EN дополнительно показывать долю по Chordonomicon («≈+11% песен»).
- Нет источника BPM для русских песен (автопрокрутка, метроном): sources-en предлагает Deezer как источник BPM. Живая проверка (verified_live=true): у Кино «Группа крови», Звери «Районы-кварталы», ДДТ «Что такое осень» и Ляпис Трубецкой «Воины света» bpm=0, у Сплин «Выхода нет» 170.14 (скорее всего двойной темп). У EN значения есть: Believer 124.91, Let It Be 137.81. Получается, автопрокрутка «по BPM» для русского репертуара почти всегда без данных. => Deezer не брать. Источники темпа по убыванию приоритета: (1) syncedLyrics из LRCLIB — время каждой строки, привязка к строкам листа нечётким сравнением текста; (2) strummings[].bpm у UG и bpm у holychords; (3) tap-tempo на экране песни, сохраняется для песни; (4) калибровка тапом «следующая строка».
- Щелчки метронома попадают в микрофон при анализе ритма и автосчёте OMC: tech-audio велит отключить echoCancellation, а метроном играет из динамика. Микрофон услышит каждый щелчок как атаку, причём ровно в долю, где должен быть и удар по струнам. Ритм-фидбек и автосчёт смен покажут ложную идеальную точность. Этот эффект ни одно измерение не учло. => Щелчок делать узкополосным синусом 2.5–3 кГц длиной 15–20 мс. Атаки детектировать в полосе 150–1500 Гц, после BiquadFilter type 'notch' на частоте щелчка. Добавить режим «тихие такты»: отсчёт вслух, потом визуальный пульс или navigator.vibrate без звука — это ещё и полезное упражнение. Для замеров рекомендовать проводные наушники. Пороги проверять на телефоне владельца.

- Офлайн-поведение в деталях: tech-audio описал precache и IndexedDB, но не сказал, что происходит при поиске без сети, со ссылками, присланными офлайн, с обновлением SW во время занятия и с миграциями схемы. При мобильных «белых списках» и сбоях ОАК в BY офлайн — основной режим, а не крайний случай. => (1) Поиск без сети: только по библиотеке и недавним результатам, источники показывать с пометкой «нет сети». (2) Ссылки из Share Target без сети класть в хранилище pendingImports и обрабатывать по событию 'online' или при следующем запуске. (3) Новый SW не активировать во время сессии: тост «Обновление готово» и skipWaiting только по нажатию. (4) Схему IndexedDB версионировать, миграции в upgrade(), перед миграцией автоматически экспортировать JSON. (5) Звуковые сэмплы кешировать лениво, KS-синтез работает всегда. (6) Если persist() отклонён, раз в неделю напоминать об экспорте.
- Доступность (accessibility): Ни одно измерение её не разбирало, кроме размеров тап-целей. Ключевые функции — тюнер, цвет незнакомого аккорда, мигание метронома — построены на цвете и анимации. => Диаграммы аккордов: <svg role=img aria-label="Am: G — 2 лад средним; C, E, A открыты"> плюс текстовая запись '2000'. Информацию не передавать только цветом: у тюнера текст «в строю ✓ / выше на 12 центов», у незнакомых аккордов рамка и иконка. Визуальная доля метронома — маленькая точка, без полноэкранной вспышки: при 200 BPM это больше 3 вспышек в секунду, порог WCAG 2.3.1. Размеры в rem и учёт системного масштаба текста, контраст ≥4.5:1 для текста песни в обеих темах. lang="ru|be|uk|en" на блоке текста песни. Альтернатива непрерывной прокрутке — постраничный режим «по секциям» (для prefers-reduced-motion и при трудностях с чтением). Все контролы доступны с клавиатуры, вибрация на отсчёт как опция.
- Стратегия тестирования парсеров и аудио: Есть только canary (infra) и упоминание синтетических фикстур. Нет модульных и свойственных тестов нормализатора, golden-тестов адаптеров и регрессии аудио-порогов. Дрейф разметки (amdm уже перешёл с <b> на div.podbor__chord) будет ломать адаптеры молча. => node --test плюс fast-check 4.10.2 (MIT, verified_live=true npm view). (3) Golden-тесты для каждого адаптера: HTML → ожидаемый ChordPro (реальные фикстуры приватно, синтетические в публичной части). (4) ChordSheetJS как devDependency-эталон: сравнивать позиции аккордов на корпусе, в бандл не попадает. (5) Аудио: синтетика KS плюс 20–30 собственных записей укулеле владельца (на них нет чужих прав) для регрессии порогов clarity, атак и хромы. - Модель данных, готовая к синхронизации и повторному разбору: Схемы у tech-audio и infra-legal фрагментарны, «произведение» и «версия» не разделены. Синхронизировать всё, кроме versions.rawText и versions.chordpro для загруженных с сайтов песен (только URL и метаданные), а вставленный пользователем текст синхронизировать.
