# infra-legal

## summary
Основной прокси для песен лучше поставить на Vercel Functions (Hobby). Использовать стандартный адрес *.vercel.app без кастомного домена и регион fra1. Лимиты Hobby сверены с документацией 14.11.2026: 1M вызовов, 4 ч Active CPU, 100 GB трафика, Runtime Cache 1M чтений и 200K записей в месяц. По сообщениям пользователей, в РФ *.vercel.app открывается, а кастомные домены на части IP Vercel заблокированы.
Cloudflare Workers годится только как запасной вариант для Беларуси. В России Cloudflare троттлится примерно до 16 KB на соединение, и в документации Cloudflare от 23.04.2026 это описано как продолжающееся. Deno Deploy закрывается примерно в апреле 2027 после сделки с Cloudflare. У Netlify нет преимуществ перед Vercel. Neon Function как прокси для песен бессмысленна: клиент из BY/RU всё равно ходит туда через relay. Свой VPS в РФ с ноября 2026 режут целыми подсетями хостеров (Hetzner, DO, OVH и др.).
Живые проверки делал с американского IP DigitalOcean (это датацентр). amdm.ru, mychords.net, Ultimate Guitar, chordie, ukulele-tabs, gl5, akkords.pro и holychords отдают 200. e-chords (WAF Cloudflare), ukutabs и chordify (challenge) отвечают 403. amdm на стандартный curl UA возвращает 520, а на честный кастомный UA отдаёт 200. Часть .ru-сайтов из-за рубежа недоступна (akkordbard.ru, ukulele.ru, pesni.guru). CORS-заголовков нет ни у одного песенного сайта.
С юридической стороны: тексты песен охраняются (в РФ и в действующей редакции закона РБ — жизнь автора плюс 70 лет). Опора для приложения — исключение для личного использования: ст. 1273 ГК РФ и ст. 35 закона РБ № 262-З. Пользователь делает одну копию для себя, и хранится она только у него на устройстве. ToS Ultimate Guitar прямо запрещает сохранять контент на устройство, разрешены только ссылки, поэтому UG — только переход по ссылке. Правила amdm запрещают копирование и распространение, но сам сайт ссылается на некоммерческое обучение игре.
Схема с минимальным риском такая. Песня загружается только по нажатию пользователя, по одному URL и только через разрешённые адаптеры. Контент хранится только в IndexedDB, на сервере не кешируется, у каждой песни есть атрибуция и ссылка на источник. Публичного каталога нет. Встроенный стартовый набор — песни из общественного достояния. Вставка или импорт ChordPro и простого текста работает как всегда легальный запасной путь.
Синхронизация для MVP: только локально (IndexedDB, navigator.storage.persist, экспорт и импорт JSON), но с моделью данных, готовой к синхронизации. На втором этапе — существующий Neon через тот же Vercel relay в отдельной схеме, причём синхронизировать только прогресс, метаданные и текст, введённый самим пользователем.
Мониторинг адаптеров: ежедневная canary-проверка в GitHub Actions, при поломке создаётся GitHub Issue (приходит письмо). На Vercel Hobby runtime-логи живут 1 час, на них полагаться нельзя. В приложении — цепочка деградации: Vercel → CF Worker → «открыть оригинал / вставить текст».

## recommendations
- [must] Прокси: Vercel Functions, *.vercel.app, регион fra1: Отдельный Vercel-проект (например uke-proxy) на Hobby с vercel.json {"regions":["fra1"]}. По умолчанию регион iad1, на Hobby доступен ровно один регион. Кастомный домен не нужен: в РФ блокируются IP апексов кастомных доменов (216.198.79.1 числится в реестре РКН с 04.03.2024), а *.vercel.app резолвится в 216.198.79.x/64.29.17.x (.195/.67) и, по сообщениям пользователей, работает. Код пишется в стиле Web-standard export default { fetch(req) }, чтобы тот же модуль без изменений шёл в Cloudflare Workers. Таймаут к источнику AbortSignal.timeout(8000).
- [must] Закрытый allowlist-прокси, а не open proxy: Каждый адаптер объявляет host и регулярку пути (например amdm: ^/akkordi/[a-z0-9_]+/\d+/[a-z0-9_]+/$), всё остальное получает 403 NOT_ALLOWED. Ключ устройства передаётся в заголовке X-Uke-Key, а не в Authorization (с Authorization CDN не кеширует). Сверка идёт по sha256 в env PROXY_KEY_HASHES, ключ пользователь вводит один раз в настройках PWA. CORS: Access-Control-Allow-Origin строго https://<user>.github.io, Vary: Origin, OPTIONS с Access-Control-Max-Age: 86400. Дополнительно одно правило WAF Rate Limiting (на Hobby 1 правило на проект, фиксированное окно 10 с–10 мин, ключ IP/JA4), например 30 запросов за 60 с.
- [must] Парсинг на сервере, компактный JSON: Прокси отдаёт не сырой HTML (у amdm страница песни ~85 KB, у UG ~288 KB), а нормализованный JSON на 3–15 KB: {ok, source:{site,url,title,artist,fetchedAt}, adapter:{id,version}, sheet:{format:'chords-over-lyrics'|'chordpro', text}} либо {ok:false, code:'NOT_ALLOWED'|'BLOCKED'|'PARSE_FAILED'|'UPSTREAM_4xx'|'UPSTREAM_5xx'|'TIMEOUT', retryAfter?}. Маленький ответ переживает пакетный троттлинг ТСПУ и мобильные сети. Парсер: node-html-parser 9.0.7 (MIT) или linkedom 0.18.15 (ISC), оба работают и в Workers. cheerio 1.2.0 (MIT) тяжелее. Пример селектора amdm (проверен вживую): pre[itemprop=chordsBlock].
- [must] Вежливый обход: Честный UA, например 'UkeTrainer/0.1 (+https://<user>.github.io/uke/about; personal, non-commercial)', без личного email. Подменять UA на Chrome не нужно: amdm принял кастомный UA (200), а стандартный curl UA получил 520. Не чаще 1 запроса в 5 с на хост (у amdm для * указан Crawl-Delay: 5), одно соединение на хост, без префетча и массового обхода, один запрос на одно действие пользователя. robots.txt кешировать на 24 ч и проверять через robots-parser 3.0.1 (MIT). Обход /search у amdm (Disallow для *), /search.php у UG, /?s= и /wp-json/uku/v1/ у ukutabs запрещён robots. Поиск строить на страницах-индексах артистов или на источниках, где поиск разрешён.
- [must] Контент хранится только на устройстве, без серверного кеша: На ответах с контентом песен ставить Cache-Control: private, no-store. CDN-кеш Vercel (s-maxage) срабатывает до проверки ключа, и прокси превратился бы в публичное зеркало чужого контента. Runtime Cache (@vercel/functions 3.11.3, getCache) использовать только для robots.txt, результатов поиска и негативных ответов с TTL до 1–24 ч. На Hobby этот кеш общий для всех проектов команды, поэтому relay и прокси вытесняют записи друг друга. Песни хранить в IndexedDB (idb-keyval 6.3.0, Apache-2.0), плюс вызывать navigator.storage.persist().
- [must] Атрибуция и ссылка на источник всегда: В каждой песне показывать сайт, исходный URL, автора подбора, если есть, и дату загрузки, плюс кнопку «Открыть оригинал». Для Ultimate Guitar, e-chords, ukutabs и chordify адаптеры не делать, только поиск ссылки и переход: ToS UG (ред. 24.08.2026) разрешает «link to, but not replicate» и запрещает сохранять контент «onto any … memory or device», а остальные три блокируют IP датацентров (403).
- [must] Всегда легальный запасной путь: вставка и импорт плюс стартовые песни из общественного достояния: Поле вставки простого текста (формат «аккорды над строками») и импорт ChordPro (.cho/.chordpro/.txt). Web Share Target в manifest.json, чтобы на Android делиться в PWA URL или выделенным текстом из Chrome. Стартовый набор — народные песни (например «Калинка» Ларионова, 1860, «Во поле берёза стояла», «Ой, то не вечер»), в США — произведения, опубликованные до 1930 года включительно (1930 год перешёл в общественное достояние 01.01.2026), например «Oh! Susanna», «Amazing Grace», «You Are My Sunshine» не подходит (1939). Аккорды набора писать самим в ChordPro. Если использовать chordsheetjs 18.0.0, учесть лицензию GPL-2.0-only.
- [must] Синхронизация в MVP: только локально плюс экспорт/импорт JSON: IndexedDB, navigator.storage.persist(), экспорт {schemaVersion, exportedAt, progress[], songs[], settings} через скачивание или navigator.share({files}) в «Избранное» Telegram или облако, импорт со слиянием по id. Модель сразу делать готовой к синхронизации: у каждой записи id (uuid), updatedAt, deleted (tombstone), deviceId. Тогда второй этап не потребует миграции.
- [must] Canary-мониторинг адаптеров и деградация: GitHub Actions по расписанию раз в день (например '17 4 * * *') запускает node scripts/canary.mjs, который вызывает /api/health?deep=1 с CANARY_KEY. Для каждого адаптера на одном эталонном URL проверяются: HTTP 200, найден селектор, ≥8 токенов аккордов по регулярке ^[A-H](#|b)?(m|maj|min|dim|aug|sus|add)?\d*(/[A-H](#|b)?)?$, ≥6 строк текста, схема JSON. При сбое gh issue create/edit с меткой adapter-broken, письмо приходит независимо от блокировок Telegram. В PWA файл adapters.json на GitHub Pages ({id, enabled, minAppVersion}) работает как рубильник без передеплоя прокси. В UI при PARSE_FAILED/BLOCKED показывать «Источник изменился» с кнопками «Открыть оригинал» и «Вставить текст».
- [must] Секреты только на сервере и в CI: В бандле PWA на GitHub Pages ничего секретного нет, бандл публичный. В env Vercel: PROXY_KEY_HASHES, CANARY_KEY, ALLOWED_ORIGIN, UA_CONTACT_URL, на втором этапе NEON_*/RELAY_*. В GitHub Secrets: PROXY_URL, CANARY_KEY. Ключ устройства хранится в IndexedDB или localStorage устройства и отзывается удалением хеша из env.
- [should] Запасной прокси на Cloudflare Workers (только для BY): Тот же модуль деплоится через wrangler 4.162.0 на *.workers.dev. Лимиты Free (проверены): 100 000 запросов в сутки, 10 мс CPU на запрос, 50 подзапросов, 128 MB, KV 100k чтений и 1k записей в сутки, 1 GB. Клиент пробует Vercel (таймаут ~10 с), потом Worker, потом предлагает вставить текст. Риски: 10 мс CPU мало для разбора HTML на 300 KB. Сайты на Cloudflare могут блокировать подзапросы Workers по cf.worker.upstream_zone. В РФ workers.dev попадает под троттлинг, поэтому для РФ это не запасной вариант.
- [should] Отдельный Vercel-проект, код токенов взять из relay: Не смешивать прокси песен с существующим sync-relay: если на проект придёт жалоба правообладателя или его остановят за fair use, синхронизация основного приложения не пострадает. Модуль проверки device-токенов скопировать или вынести в общий пакет. Hobby разрешает несколько проектов, но учитывать общий Runtime Cache и общие лимиты команды (1M вызовов в месяц на всё).
- [should] Второй этап синхронизации: существующий Neon через relay: Тот же Neon-проект, новая схема uke: uke_progress(user_id, key, value jsonb, updated_at, deleted) и uke_songs(user_id, song_id, meta jsonb, user_text text null, updated_at, deleted). Слияние last-write-wins по updated_at для каждой записи, курсор по max(updated_at). Эндпоинты /api/uke/pull и /api/uke/push проходят через существующий Vercel relay в Neon Function или Data API. На сервер не синхронизировать полученные с сайтов тексты: только URL и метаданные (тональность, каподастр, транспонирование, заметки) и текст, вставленный самим пользователем. Другое устройство заново загрузит песню по URL. Free-план Neon с запасом: 1 GB на проект, 100 CU-ч в месяц, Functions 1M вызовов и 10 активных capacity-часов, egress 5 GB.
- [should] Тестовые фикстуры — синтетические: Сохранённые HTML-страницы с чужими текстами в публичном репозитории — это распространение. Для unit-тестов адаптеров хранить минимальные синтетические HTML той же структуры (например pre[itemprop=chordsBlock] с текстом песни из общественного достояния). Проверку на живых страницах оставить canary-задаче.
- [could] Букмарклет и Share Target как путь извлечения на клиенте: Букмарклет на десктопе читает document.querySelector('pre[itemprop=chordsBlock]').innerText на открытой пользователем странице и открывает PWA с текстом во фрагменте URL (#data=…, на сервер не уходит). Контент получает браузер самого пользователя, без серверного запроса. Это главный путь, если приложение станет многопользовательским.
- [could] LRCLIB как помощник для текстов: https://lrclib.net/api/search?q=… и /api/get?artist_name=&track_name= отдают 200 и access-control-allow-origin: * (проверено), поэтому можно вызывать прямо из браузера, без прокси. Аккордов там нет, сайт за Cloudflare (в РФ троттлинг, но JSON небольшой). Подходит только для подсказки текста при ручной расстановке аккордов.
- [avoid] Не использовать Deno Deploy, Netlify, Neon Function как прокси, VPS и обход Cloudflare: Deno Deploy: на deno.com/pricing баннер «Deno Deploy will be sunset in April 2027» (Deno вошёл в Cloudflare 09.10.2026). Netlify: кредитная модель (300 кредитов в месяц), по отзывам на форуме деплои ставятся на паузу, преимуществ нет. Neon Function: клиент из BY/RU получает 403 и всё равно идёт через relay, лишний хоп. VPS: в РФ подсети Hetzner, DO, OVH, Vultr режутся по числу пакетов (замер 5–6.11.2026). Headless-браузер или решатель Cloudflare challenge (chordify, e-chords): это нарушение ToS (UG прямо запрещает circumvent content protection methods) и обход антибот-защиты.
- [avoid] Не делать публичный CDN-кеш, публичный каталог и массовую предзагрузку: Никакого s-maxage на контенте, никакого общего «каталога песен» на сервере, никакого краулинга по sitemap для поиска. Это превращает личное использование (ст. 1273 ГК РФ, ст. 35 закона РБ 262-З) в воспроизведение и доведение до всеобщего сведения оператором сервиса.

## items
- Vercel Functions (Hobby) (https://vercel.com/docs/limits/fair-use-guidelines) [хостинг прокси] live=True
  facts: Лимиты Hobby (документация обновлена 12.11.2026): Function Invocations 1 000 000 в месяц, Active CPU 4 ч, Provisioned Memory 360 GB-ч, Fast Data Transfer 100 GB, Fast Origin Transfer 10 GB. Runtime Cache: 1M чтений и 200K записей (по 8 KB) в месяц, объект до 2 MB, общий для всех Hobby-проектов команды, при превышении кеш выключается до конца периода. CDN-кеш: ответ до 10 MB, только GET/HEAD без Authorization и без set-cookie. Функции работают в одном регионе (по умолчанию iad1, через vercel.json regions можно выбрать fra1). Cron раз в сутки с точностью ±59 мин. Runtime-логи хранятся 1 час. WAF Rate Limiting: 1 правило на проект (из 3 custom rules), окно 10 с–10 мин, 1M разрешённых запросов. Hobby только для личного некоммерческого использования. Пакеты: @vercel/functions 3.11.3 (Apache-2.0), CLI vercel 65.16.0. Доступность: *.vercel.app резолвится в 216.198.79.x/64.29.17.x. На форуме Vercel 2024–2026 пишут, что в РФ кастомные домены на части IP заблокированы (216.198.79.1 в реестре РКН с 04.03.2024), а *.vercel.app работает, в том числе на мобильных (тред от 20.09.2026). Владелец сообщает, что vercel.app открывается из Минска.
  verdict: use: основной прокси. Бесплатных лимитов хватит на порядки больше личной нагрузки, *.vercel.app доступен в BY/RU.
- Cloudflare Workers (Free) (https://developers.cloudflare.com/workers/platform/limits/) [хостинг прокси] live=True
  facts: Free: 100 000 запросов в сутки (сброс в 00:00 UTC, при превышении ошибка 1027), CPU 10 мс на HTTP-запрос, 50 подзапросов, 128 MB, 5 Cron Triggers. KV Free: 100k чтений и 1k записей в сутки, 1 GB, значение до 25 MiB. Обёртка HTMLRewriter для потокового парсинга. Подзапросы несут CF-Worker и cf.worker.upstream_zone, и сайты на Cloudflare (amdm, mychords, UG, gl5, ukulele-tabs) могут их блокировать WAF-правилом. РФ: на странице Cloudflare service-disruption (обновлена 23.04.2026) троттлинг описан как продолжающийся: «approximately 16 KB per connection», начался 09.06.2025, восстановить доступ Cloudflare не может. BY: признаков блокировки не найдено, точка присутствия MSQ (Минск) в статусе operational.
  verdict: maybe: запасной прокси только для BY. В РФ не годится, 10 мс CPU мало для тяжёлого HTML.

  facts: Free: 1M запросов в месяц, egress 20 GiB, 10 ч Active CPU, KV 1 GiB, 1M чтений и 500K записей. На странице тарифов баннер «Deno Deploy will be sunset in April 2027». По вторичным источникам, 09.10.2026 объявлено о присоединении Deno к Cloudflare, Deploy закрывается примерно через 6 месяцев, платным клиентам помогают с миграцией на Workers.

## risks
- Все живые проверки сделаны с US IP DigitalOcean (AS14061), а не с IP Vercel/AWS fra1 и не из Минска. Сайты могут по-разному относиться к ASN AWS (у e-chords блок по ASN уже есть), а в BY/RU возможна своя картина.
- РФ: ТСПУ режет соединения к зарубежным хостерам по числу пакетов (замер 5–6.11.2026: ~25 пакетов на домашнем интернете, ~8 на мобильном). AWS и Vercel пока не в списке, но расширение вероятно. Cloudflare троттлится с 09.06.2025 и, по документации Cloudflare от 23.04.2026, это продолжается. Мобильные «белые списки» отрезают всё зарубежное, поэтому PWA обязана полноценно работать офлайн.
- Кастомный домен на Vercel может оказаться на IP из реестра РКН (216.198.79.1 с 04.03.2024). Только *.vercel.app по отзывам доступен, официальных гарантий нет.
- BY: ОАК периодически закрывает доступ из-за рубежа к белорусскому виртуальному хостингу (25–27.01.2026, 24–26.03.2026). В эти окна .by-источники с прокси за границей недоступны. GitHub Pages из BY были недоступны в 2020 и 2021.
- Источники меняют HTML и усиливают антибот-защиту: в robots amdm есть отсылка к docs/anti-bot.md, стандартный curl UA уже получает 520. Адаптер может сломаться без предупреждения, а на Hobby runtime-логи живут 1 час.
- Правовой риск: правила amdm запрещают копирование, ToS UG запрещает хранить на устройстве. Для одного личного пользователя это прежде всего риск бана IP или аккаунта, а не иска, но формально это нарушение условий.
- Если приложение откроется другим людям, оператор сам воспроизводит контент и доводит его до всеобщего сведения. Исключение для личного использования (ст. 1273 / ст. 35) на это не распространяется. Это 187-ФЗ с вечной блокировкой через Мосгорсуд, DMCA-жалобы в Vercel и GitHub. Кроме того, Vercel Hobby только для некоммерческого использования (нужен Pro $20/мес), 152-ФЗ требует локализации ПД граждан РФ при аккаунтах, в BY действует закон № 99-З о ПД.
- На Vercel Hobby Runtime Cache общий для всех проектов команды: прокси и существующий relay вытесняют записи друг друга, при превышении 1M/200K кеш отключается до конца периода.
- Синхронизация через Neon зависит от relay (единая точка отказа) и от того, что Neon не расширит геоблок на исходящие запросы или аккаунты. Публичного документа Neon о блокировке BY/RU не нашёл.
- Расписание GitHub Actions в публичном репозитории отключается после 60 дней без коммитов, и canary-проверка молча перестаёт работать.
- Публичные тестовые фикстуры с реальными страницами песен — это распространение чужого контента.
- chordsheetjs под GPL-2.0-only: при встраивании PWA должна распространяться на совместимых условиях.
